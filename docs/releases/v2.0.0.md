# v2.0.0

The parser no longer depends on the Carnatic package, and the library splits into layers you can
import on their own. `notations/core` is the runtime model with no parser and no renderer, and
`notations/parser` is the DSL parser and `load()` without the renderer. The major bump is for one
change: a `Parser` you construct yourself must now be given its gamakas. `load()` and `parse()`
work as before, so code that only calls those needs no change. The release also moves
`DockViewPlayground` onto `@panyam/tsappkit-dock`, which changes its peer dependencies.

## Breaking

- **`new Parser()` needs its gamakas** (issue 18, PR 88). The parser used to import the whole
  `carnatic` package, renderer included, to read `~` tokens. It now declares an
  `EmbellishmentParser` and takes one as an option, and `carnaticGamakas` provides the Carnatic
  ones. A bare `new Parser()` reports each `~` as an error:

  ```
  No embellishment parser for ~/: pass embellishments to Parser, or use load() or parse()
  ```

  Migration:

  ```ts
  // 1.x
  const parser = new Parser();

  // 2.0
  import { Parser, carnaticGamakas } from "notations";
  const parser = new Parser({ embellishments: carnaticGamakas });
  ```

- **`DockViewPlayground` peer dependencies** (PR 58). `dockview-core` goes from `^4.0.0` to
  `>=4.13 <9`, and `@panyam/tsappkit-dock ^0.7.40` is a new peer. Both stay optional, so only
  users of `notations/web/dockview` need them. On dockview-core 8, take the stylesheet from the
  `dockview` package (`dockview/dist/styles/dockview.css`). Layouts saved by 1.x aren't restored:
  the save key is now `${storageKey}-v${layoutVersion}`.

## Added

- **`notations/core` and `notations/parser`** (issue 18, PR 88). For `import { load }`, the main
  entry bundles to 256 KB minified (72 KB gzipped), and `notations/parser` to 240 KB (69 KB).
  `notations/core` bundles to 29 KB (8 KB) for code that walks a model: `AtomIterator`, cycles
  and the beat layout. The parse bundle is mostly the grammar libraries and yaml; issue 87 tracks
  yaml.

  ```ts
  import { load } from "notations/parser";
  import { AtomIterator } from "notations/core";
  ```

- **Front matter declares defaults** (issue 52). `cycle`, `beatDuration` and `breaks` in front
  matter mean what the matching commands mean at the top of the body.
- **`NotationBlock` shows parse errors** in a `.notation-error` box with `role="alert"`, and in
  edit mode Ctrl+Enter (Cmd+Enter) applies and Escape cancels.
- **`DockViewPlayground`**: a `consoleHeight` option (PR 63) and a `dock` property (PR 58).
- **`ParseError`** is exported as a type (PR 67).

## Changed

- **Bars written without spaces** read whole numbers: `\cycle("10|4")` is bars of 10 and 4
  beats. Anything that isn't a beat count or beat spec in a bar is an error (issue 59).
- **The old `"x">>` and `<<"x"` markers** are parse errors that name the `\@label(...)`
  replacement (issue 59).
- **`Utils.parseSyllable`** follows the DSL's underscore rule: `"S_N_D"` is one syllable, and a
  lone `_` is silence (issue 33, PR 68).
- **Accessibility**: `NotationBlock`'s source and output boxes take keyboard focus and carry a
  label, and the playground console is a focusable `role="log"` (PR 67).
- **`NotationBlock.updatePreview()` and `applyEdit()`** return a Promise, and the output carries
  `aria-busy` while a render is pending.
- **No console noise**: the parser no longer prints parsed front matter or skipped embellishments,
  and `NotationBlock` no longer logs on every render.

## Fixed

- **A lone `_` is silence**, not a visible literal; **`|` and `||`** in a line are accepted and
  ignored, since the renderer draws bars from the cycle; and **an unknown command** is a
  ParseError rather than an exception (PR 32).
- **A bad command param no longer makes `load()` throw** (issue 69). `\cycle("|4x|")`, `\cycle()`,
  `\role()` and a bad front matter cycle each report a ParseError naming the command.
- **`"1.">> s r g m` lost its notes** without an error (issue 59).
- **`NotationBlock` inserted source, `id` and `caption` as HTML** (issue 30). It builds the DOM
  directly now.
- **`Cycle` had no `toString`**, so the serializer wrote `\cycle("Entity(id = 19)")` (issue 59).

## Docs site

The docs site isn't part of the published package, but it changed a lot in this range: the
Photo Transcribe demo and its CLI, Pagefind search, a phone-width header drawer, WCAG AA colours
and keyboard access, lazy loading of the notation code, a glossary, and tests that fail when an
example doesn't parse, runs swaras together, names a tala with the wrong cycle, or links to a page
that doesn't exist.

## Build

npm publishing runs from release tags through GitHub Actions with trusted publishing (PR 35,
PR 37). pnpm is 12, pinned by hash, with a minimum release age and trust checks for dependencies
(PR 38).
