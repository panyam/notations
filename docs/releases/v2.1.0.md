# v2.1.0

This release gets rendered notation out of the page. `notations/export` prints a notation on its
own and exports it as SVG or PNG, and the playgrounds have buttons for each. It also drops the
`yaml` package from the parser, which cuts the `notations/parser` bundle by about 40%.

The bump is minor. One change can still break a document: front matter is now read by a small
parser for flat `key: value` lines, so nested YAML in front matter is a parse error. Nothing in
the docs or in notation_demos uses it. Read "Front matter" below before upgrading if your
documents might.

## Front matter

- **Front matter reads flat `key: value` lines only** (issue 87, PR 99). A value can be a quoted
  or plain string, a number, `true`, `false`, `null`, or a list on one line such as `[8, 8]`, and
  it reads as YAML reads it. These now give a parse error that names the line, where 2.0 accepted
  them:

  ```
  ---
  ragam: Kedaram
  details:          # nested map
    arohanam: S R G P D S.
  breaks:           # block list
    - 8
    - 8
  notes: |          # multi-line string
    first line
  ---
  ```

  ```
  front matter line 4: nested values are not supported in front matter
  front matter line 6: nested values are not supported in front matter
  front matter line 7: nested values are not supported in front matter
  front matter line 8: notes: "|" needs quotes; nested lists, maps, anchors and tags are not supported
  front matter line 9: nested values are not supported in front matter
  front matter breaks: Breaks command must be a list of integers
  ```

  `ragam` still applies, and none of these errors throws out of the parser.

  Migration: put each value on one line. Write a list as `breaks: [8, 8]`. Flatten a nested map
  into separate keys, such as `arohanam: "S R G P D S."`.

- **The parse bundle is smaller.** `import { load }` from `notations/parser` goes from 247 KB to
  151 KB minified, and from 71 KB to 42 KB gzipped. `yaml` is no longer a dependency.

## Added

- **`notations/export`** (issue 74, PR 95, PR 100). It needs a browser and doesn't pull in
  `notations/web`.
  - `printNotation(source)` opens the print dialog with the notation alone. Every line scales by
    one factor, so the widest line fills the page. "Save as PDF" in the dialog gives a PDF.
    `preparePrint` sets up that print-only copy without opening the dialog.
  - `exportSVG(source)` returns one standalone SVG in the light theme, with no `foreignObject`.
    Headings and front matter become SVG text, keeping bold and italic.
  - `exportPNG` draws that SVG at twice its size. `downloadSVG` and `downloadPNG` save either as a
    file.
- **Playground print and export** (issue 74). `DockViewPlayground` has `print()`, `downloadSVG()`
  and `downloadPNG()`, and Ctrl/Cmd+P prints the notation alone. The side-by-side and photo
  playgrounds have Print / PDF, SVG and PNG buttons.
- **`NotationViewConfig.marginAlign`** (issue 97, PR 98). It sets margin labels to `left`,
  `center` or `right`, through the `--notation-margin-align` CSS variable.

## Changed

- **The margin column fits its labels** (issue 97, PR 98). It used to take a share of the table's
  spare width, so printed labels sat far from their notation. Labels are now right-aligned by
  default.
- **`@panyam/tsappkit-dock` peer range is `^0.7.44`** (issue 90, PR 93). Older versions put a
  focusable close button inside each dock tab, which axe reports as `nested-interactive`.

## Fixed

- **One bad command no longer blanks the playground** (issue 94, PR 96). `SideBySideEditor.render()`
  reports the errors through `onParseError`, then renders whatever parsed and calls
  `onNotationParsed`. It still returns `false` when there were errors.
- **Dock tabs hold no nested control** (issue 89, PR 91), from tsappkit-dock 0.7.44.

## Development

- `pnpm run exercise:48` runs the end-to-end mission exercise (issue 48) in headless Chromium
  against the live docs site, or a local one with `--base` (issue 92, PR 99).
